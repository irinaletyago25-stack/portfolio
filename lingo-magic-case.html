01 · Проблема

Разрыв
между
авторами

⚠
Реальная ситуация на старте
60+ авторов-экспертов из разных стран присылали контент, каждый в меру своего понимания «хорошего задания». Одни давали задачи уровня C2, другие A1 — в одном модуле. Инструкции были то двухстрочными, то абзацными. Дистракторы — либо случайными, либо слишком очевидными. Единого ориентира не было вообще.
Симптом 1
Разный уровень сложности
Задания A1 и C1 стояли рядом без логики прогрессии. Ученик не понимал, вырос ли он — или просто попал на лёгкое задание.
Симптом 2
Дистракторы не работали
Неверные варианты были либо очевидно нелепыми (угадать за 1 сек.), либо слишком близкими. Обе крайности — педагогический провал.
Симптом 3
Тон не был единым
Один автор писал «Выберите правильный ответ», другой — «Нажмите на верный вариант», третий — «Укажите». Пользователь учился интерфейсу, а не языку.
02 · Дизайн-решение

Почему
стандарты —
а не просто
больше ревью

Вариант А · Отклонён
Индивидуальная обратная связь
Давать каждому автору комментарии после каждого задания. Работало на 5–10 авторах. При 60+ я бы стала узким местом всего процесса — и качество определялось бы скоростью моей проверки.
✗ Не масштабируется
Вариант Б · Отклонён
Подробный текстовый гайд
Написать длинный документ «Как делать хорошие задания». Проблема: авторы — эксперты-предметники, не методисты. Длинный текст не читают или читают, но не применяют — слишком абстрактно.
✗ Не применяется на практике
Вариант В · Выбран
Система: стандарты + шаблоны + чеклист + онбординг
Создать не правила, а инструменты: авторы заполняют шаблон, который сам направляет структуру; чеклист — для самопроверки перед сдачей; онбординг — с примерами хорошего и плохого. Я проверяю по единому критерию, а не по ощущению.
✓ Масштабируемо + обучает
💡
Ключевой педагогический принцип
Документ со стандартами я проектировала как учебный материал — с примерами, объяснением «почему», практическими заданиями. Он должен был обучать, а не просто регламентировать. Это и есть педдизайн, применённый к самому процессу создания контента.

04 · Артефакт — Стандарты качества

Две категории
стандартов

T1Реальный контекст
Каждое задание привязано к конкретной жизненной ситуации (кафе, аэропорт, работа). Голое слово без контекста — не допускается.
✓ Так
"You're checking in at the hotel. The receptionist asks: ___"
✗ Не так
"Translate: reception"
T2Правдоподобные дистракторы
3 неверных варианта из одной семантической группы. Угадываемые (животные вместо мебели) — возврат на доработку.
✓ Посуда: cup / plate / bowl / mug
Все — ёмкости. Надо думать.
✗ cup / dog / sky / run
Случайные слова — угадываемо.
T3Обратная связь на каждый вариант
Для каждого неверного ответа — конкретное объяснение. «Неверно, попробуй ещё» — не считается.
✓ «Plate» — для еды, не напитков. Для кофе используй «cup».
✗ «Неправильно. Попробуй снова.»
T4CEFR-привязка и прогрессия
Каждое задание размечается уровнем (A1–C1). Сложность в модуле растёт последовательно. Скачок больше одного уровня — на пересмотр.
✓ Модуль: A2 → A2+ → B1 (линейно)
✗ A1 → C1 → A2 (хаос)
L1Единая терминология действий
Глоссарий глаголов-команд. Один тип действия — один глагол везде. Авторы не изобретают синонимы.
✓ Всегда: выберите / вставьте / соедините / перетащите
✗ «Нажмите / укажите / отметьте / выделите» — все об одном
L2Длина инструкции
Инструкция к заданию — максимум 2 строки. Активный залог. Без вводных конструкций. Ученик читает инструкцию 1 раз и сразу понимает задачу.
✓ «Выберите правильное слово для диалога»
✗ «В данном упражнении вам необходимо будет выбрать из предложенных вариантов наиболее подходящее слово…»
L3Поддерживающий тон
Обратная связь — как хороший учитель: объясняет причину ошибки, не осуждает. Восклицательные знаки в победных сообщениях — уместны. В ошибках — нет.
✓ «Почти! 'Plate' — для еды. Попробуй 'cup' для напитков 🍵»
✗ «Ошибка! Это неправильный ответ!!!»
L4Культурная нейтральность
Примеры и имена персонажей — нейтральные для всех рынков (15+ языков). Отсутствие культурно специфичных метафор без объяснения.
✓ Имена: Alex, Maria, Kim — нейтральные
✗ Отсылки к специфичным культурным явлениям без адаптации
05 · Система доставки стандартов

Три канала
до каждого автора

Стандарты не работают, если лежат в папке. Нужна система доставки — разная для разных ситуаций.

01
Документ стандартов
Живой документ в Notion/Google Docs. Не просто правила — каждый пункт с примером «так» и «не так». Структурирован как учебный материал: от простого к сложному.
NotionGoogle DocsПримеры
02
Онбординг новых авторов
Новый автор проходит мини-онбординг: читает стандарты + делает тестовое задание. Первые 3 сданных задания — с расширенным ревью. Потом переходит на стандартный процесс.
Тестовое заданиеРасширенное ревью ×3
03
Чеклист ревью
Авторы проверяют работу сами перед сдачей. Я проверяю по тому же чеклисту. Единый критерий снимает субъективность и ускоряет ревью в 2–3 раза.

Как я проверяю гипотезы
